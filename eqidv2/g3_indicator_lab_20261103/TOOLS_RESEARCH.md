# Tool research for the G3 indicator study

Checked **3 November 2026** against official repositories, tagged licenses, publisher package metadata and project documentation. Release names and dates below are observed values, not an installation request. The exact retrieved metadata, dependency declarations and relevant source excerpts are saved in [tools_sources.json](tools_sources.json), including retrieval time and URLs.

**Decision:** use the existing NumPy/pandas feature code, native strategy replay, and installed scikit-learn for the first interpretable model. No external project reviewed here has been shown to reproduce this repository's complete execution contract without adaptation and parity testing. No package was installed, upgraded or cloned in this tool evaluation.

## Local environment and smallest useful set

Read-only inspection found Windows x64, **Python 3.12.10**, NumPy **2.0.1**, pandas **2.2.2**, SciPy **1.18.0**, and scikit-learn **1.9.0**. LightGBM, TA-Lib, vectorbt, pyqlib, RD-Agent, torch and transformers were absent.

| Tool | Decision for this study | Useful capability | Data needed | Integration effort |
|---|---|---|---|---|
| Existing NumPy/pandas + native engine | **USE** | Causal features, grouped ranking, exact existing replay | Verified local one-/five-minute data, dated universe, native execution inputs | Low; keep explicit formulas and warmup behavior |
| scikit-learn | **USE installed 1.9.0** | Regularized logistic baseline, preprocessing pipelines, calibration diagnostics, held-out importance | Full candidate features plus realizable outcomes generated by native replay | Low; custom chronological whole-day folds are essential |
| LightGBM | **DO NOT USE YET** | Nonlinear interactions; later constrained tree challenger | Same labeled full pool, sufficient later evaluation data | Medium; new isolated dependency and extra model-selection degrees of freedom |
| TA-Lib | **OPTIONAL LATER** | Independently specified classic indicators and candlestick calculations | Clean causal OHLCV with consistent sessions and warmup | Low/medium; numerical parity and NaN behavior need verification |
| Qlib | **DO NOT USE YET** | Large factor datasets, experiment recording, model/factor workflows | A custom Indian market data provider and execution adapter | High; useful if the research platform grows, unnecessary for this small fixed study |
| vectorbt, `polakowo/vectorbt` | **DO NOT USE YET** | Fast exploratory arrays, parameter grids and portfolio statistics | Dense aligned prices/features; custom order logic for fidelity | Medium/high; dependency upgrades and execution parity would add work |
| RD-Agent | **DO NOT USE YET** | Automated research coding and factor/model proposals | Reproducible benchmark, sandbox, data, LLM access and trial budget | High; Linux workflow and many dependencies |
| FinGPT | **DO NOT USE YET** | Potential event classification/extraction after a labeled news corpus exists | Timestamped Indian announcements, manual labels, appropriate model weights | High; news feasibility and domain validation precede model choice |

These decisions assess fit and integration cost. They do not rank the projects' general quality, and none of their demonstration returns establishes an edge in this strategy.

## Compatibility and implementation assessment

### scikit-learn: use the installed package

The current publisher metadata requires Python ≥3.11 and provides CPython 3.12 Windows wheels. Its declared core dependencies include NumPy, SciPy, joblib, narwhals and threadpoolctl. The installed package can support a standardized, regularized logistic classifier without GPU dependencies. Sources: [installation](https://scikit-learn.org/stable/install.html), [package metadata](https://pypi.org/pypi/scikit-learn/json), [LogisticRegression API](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html).

Use a preprocessing pipeline fitted only on earlier training days. `TimeSeriesSplit` supplies an ordered split and a row-count `gap`, but a raw candidate table has unequal numbers of rows per day. The project must split whole sessions explicitly and purge any labels whose outcome crosses the split. Automatic default cross-validation is not a substitute. Calibration needs a separate earlier calibration window or explicitly chronological folds. Inspect calibration on later data before describing a score as a win probability. Use held-out grouped ablation/importance to assess correlated families. Sources: [TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html), [calibration](https://scikit-learn.org/stable/modules/calibration.html), [permutation importance](https://scikit-learn.org/stable/modules/permutation_importance.html).

**Replay:** no order simulator is supplied by scikit-learn. Export candidate scores into the native ranker and replay the same quota, expiry, stop, allocation and cost rules. This is the desired division of work.

### LightGBM: a later nonlinear comparison

Publisher metadata for 4.7.0 requires Python ≥3.10 and includes a Windows x64 wheel. Declared requirements include NumPy, SciPy and narwhals; the sklearn extra supports its familiar estimator interface. CPU training is sufficient for the present dataset. The official Windows guide documents supported build routes; its CUDA implementation is Linux-only, although a separate OpenCL GPU implementation exists. Sources: [Python package guide](https://github.com/lightgbm-org/LightGBM/blob/v4.7.0/python-package/README.rst), [installation guide](https://lightgbm.readthedocs.io/en/stable/Installation-Guide.html), [package metadata](https://pypi.org/pypi/lightgbm/json).

Its plausible value is nonlinear interactions between participation, extension and market regime. It also permits much more fitting than a linear baseline. Freeze a small tree/depth/leaf specification and train within earlier windows only. Feature importance measures association in the fitted model, not causal benefit. **Replay:** score producer only; native execution remains authoritative. Do not install it before the simpler baseline and sample size justify another model. An installed sklearn histogram-gradient-boosting estimator could provide a separately named nonlinear comparison without another dependency, if that experiment is predeclared.

### TA-Lib: optional formula verification and a limited feature set

The current Python wrapper provides Python ≥3.9 metadata and CPython 3.12 Windows wheels, including the underlying library in modern wheel distributions. NumPy is its main runtime dependency. The C project also supplies a Windows MSI/ZIP. Sources: [wrapper documentation](https://github.com/TA-Lib/ta-lib-python), [Python package metadata](https://pypi.org/pypi/TA-Lib/json), [C installation](https://ta-lib.org/install/c/).

It can calculate EMA, ATR, RSI and candle functions, but its function names do not guarantee identical definitions to existing code. For example, ATR smoothing, session resets, lookback periods and NaN propagation can differ from a simple rolling true-range mean. Use it only after documenting exact semantics and comparing outputs on fixed causal windows. Its pattern catalogue is a source of hypotheses, not a reason to scan dozens of patterns and choose whichever historically won. **Replay:** none; calculated features feed native selection.

### Qlib: capable platform, unnecessary migration now

Qlib provides factor expressions, datasets, model workflows and experiment recording. It has real intraday/nested-executor capability, including a one-minute example, so it should not be dismissed as daily-only. However, that example's exchange assumptions, trade units and fill prices are not this strategy's contract. Sources: [repository](https://github.com/microsoft/qlib), [high-frequency backtest source](https://github.com/microsoft/qlib/blob/main/tests/backtest/test_high_freq_trading.py).

PyPI 0.9.7 has a CPython 3.12 Windows wheel and Python ≥3.8 metadata. The installation documentation says Windows and Linux are supported, recommends Linux, and contains older Python-version wording; package files provide stronger evidence for the specific wheel than that stale sentence. Dependencies are broad: pandas/NumPy, LightGBM, MLflow, Redis libraries, CVXPY, Gym, configuration/serialization and data packages. Some optional RL dependencies require NumPy<2, conflicting with this environment. Source v0.9.8 introduces artifact/config loading changes that also need review. Sources: [installation](https://github.com/microsoft/qlib/blob/v0.9.8/docs/start/installation.rst), [package metadata](https://pypi.org/pypi/pyqlib/json), [release notes](https://github.com/microsoft/qlib/releases/tag/v0.9.8).

**Replay:** matching minute timing, core-first quotas, replacement order, stop-first ambiguity and capital would require a custom adapter plus full trade-level parity. Keep Qlib for possible future factor-workflow scale; no migration is warranted by this study alone.

### vectorbt: fast exploration with integration costs

The current 1.2.0 package supports Python ≥3.11,<3.15 but declares **NumPy ≥2.4.6 and pandas ≥3.0.3,<4**, alongside Numba, plotting and utility dependencies. That conflicts with installed NumPy 2.0.1/pandas 2.2.2 unless the environment is changed. The distributed core wheel is platform-independent; native dependencies still determine Windows compatibility. Sources: [publisher metadata](https://pypi.org/pypi/vectorbt/json), [repository](https://github.com/polakowo/vectorbt).

Array-level sweeps are useful for exploratory signals, but the ordinary signal simulator has a one-order-per-symbol-per-bar restriction and specific stop timing rules. More complex behavior requires custom order logic. Those defaults cannot establish parity with this study's trigger, entry-minute ambiguity, next-minute protection, quotas and loss locks. Sources: [portfolio API](https://vectorbt.dev/api/portfolio/base/), [stop execution semantics](https://vectorbt.dev/api/portfolio/enums/).

**Replay:** do not replace the native engine with `from_signals` and call the output equivalent. Given both dependency changes and license restrictions, the current fixed experiment is better served by NumPy/pandas and native replay. Reconsider only if a measured research bottleneck requires it.

### RD-Agent: automation does not create independent evidence

The official README says its current supported OS is Linux, with Python 3.10/3.11 tested in CI, and most scenarios use Docker. It also needs configured model access; its Python dependency set includes LiteLLM/OpenAI, data tooling, experiment infrastructure and UI packages. A Windows host could investigate a separate Linux environment later, but native Windows parity was not established here. Sources: [README](https://github.com/microsoft/RD-Agent/blob/v1.0.0/README.md), [installation/configuration](https://github.com/microsoft/RD-Agent/blob/main/docs/installation_and_configuration.rst), [publisher metadata](https://pypi.org/pypi/rdagent/json).

Its relevant capability is generating and evaluating proposed factors/models. Its automation can also increase the number of tried hypotheses, making complete trial accounting and protected later evaluation even more necessary. The project's paper describes the automated research workflow; its results do not validate Indian F&O features. Source: [original RD-Agent paper](https://arxiv.org/abs/2505.14738).

**Replay:** not a substitute for the strategy's simulator. If later adopted, its experiment interface should call the native runner with fixed data permissions and return recorded metrics. For this small study, the additional system is unnecessary.

### FinGPT: defer until news data and labels exist

FinGPT supports financial text tasks and adaptation of foundation models. The repository explicitly describes the Forecaster's US DOW30 training context; that model is not evidence for one-minute Indian stock entries. Its potential role here is extracting/classifying timestamped material events, with manual Indian examples and an abstention policy. Sources: [official repository](https://github.com/AI4Finance-Foundation/FinGPT), [original paper](https://arxiv.org/abs/2306.06031).

The current source declares Python ≥3.8,<3.13; its setup guide recommends Python3.11 on Windows and notes limitations around GPU/quantization packages. Requirements include **NumPy<2**, torch, transformers, PEFT, datasets, accelerate and bitsandbytes. That conflicts with current NumPy2.0.1. Model memory needs vary by exact weights and quantization; no GPU capacity was tested here. Cloud inference would have separate provider costs/terms. Sources: [setup.py](https://github.com/AI4Finance-Foundation/FinGPT/blob/master/setup.py), [requirements](https://github.com/AI4Finance-Foundation/FinGPT/blob/master/requirements.txt), [setup guide](https://github.com/AI4Finance-Foundation/FinGPT/blob/master/SETUP.md).

**Replay:** no native order semantics. A classifier must produce an event feature only after source publication plus plausible receipt/processing delay. It cannot reconstruct missing historical receipts or use eventual returns to label sentiment. Until a usable timestamped corpus and manually checked labels exist, a simple declared event taxonomy is more useful than adding an LLM stack.

## Adoption criteria

Use a new tool only when it solves a measured gap: a feature whose correct formula is otherwise hard to verify, a model supported by sufficient labels, or a computational bottleneck. Pin the exact version, verify its license and data/weight terms, and isolate incompatible dependencies. A successful import would demonstrate installation, not execution fidelity. Any replacement replay must match the control's candidate IDs, rank order, fills, exits, allocation and costs on fixed reference cases before its P&L is compared.

The current concrete tool choice is therefore existing numerical code plus **scikit-learn logistic regression**, scored into the **native replay engine**. Additional tooling remains conditional on evidence from that study.
